# 一页纸方案

这是学习助手。11 月中旬先解决错过竞赛截止日期，并且让别人也能用，不只是自己在本机看表。没有到期条目的那天不发消息。顺序见 [十一月中旬计划](roadmap-mid-nov.md)，模块何时做完见 [框架和范围](stack-and-scope.md)。

## 用户和范围

- 使用者是注册后的每个人。记录按账号分开，互相看不见。
- 本周信息类型只做一类。仓库默认是「竞赛」，写在 `config/settings.json` 的 `info_type`。改成「实习」或「考研」时，只改这个值。这一截仍只录入竞赛。
- 数据来源是亲手粘贴的通知，不是定时抓取。已核对的示例在 `data/records.csv`，来源清单见 [信息源清单](sources.md)，下一条怎么贴见 [第一条真实通知](first-notice.md)。
- 今天就能在本机看：`python3 -m src.timeline` 列出已核对的公历截止（剩余 N 天或已过期），`python3 -m src.reminder` 只预览今天起 7 天。这两条都不需要飞书。

## 模块何时做

- 11 月中旬：多用户、竞赛截止日、7 天提醒。账号是自建的邮箱和密码。
- 上线后一周：每周复盘。
- 12 月上旬：课程问答。Coze / Dify 抽取考试也不在中旬。
- 竞赛稳定后的阶段二：实习、考研。配置里已有这两个词，本月不改 `info_type` 去录入。
- 本月不做：个人微信机器人、定时抓取、用户之间互看、付费、Clerk、Auth0。抽取程序不能发消息，也不能改表。

## 怎么工作

1. 现在通知进 `data/records.csv`。对照原文核对之前，行是草稿。飞书多维表格是可选导出，不是查看或上线的前提。
2. 11 月中旬改成每人自己的记录：后端用 FastAPI 复用现有 Python 规则，数据库先用 SQLite，页面用 React + Vite，账号是邮箱和密码。部署见路线图。
3. 需要从长通知里抽出字段时，仍按 `extract/PROMPT.md` 的规则。输出默认「草稿」，「是否参与提醒」为「否」。相对日期写成「未找到」，并留下日期原句。网页版沿用同一规则，不在这一截接 Coze。
4. 核对后，把「核对状态」改成「已核对」。有公历日期、还想被提醒的行，「是否参与提醒」才改成「是」。
5. 提醒只看今天起 7 天、已核对、参与提醒、类型匹配的行。有行才发一条，里面有标题、截止日期、来源链接。没有行就不发。

## 怎样算这一截成立

本机时间线和 4 条已核对记录先恢复。然后按 [验收清单](checklist.md) 把多人账号、手贴、时间线页面和一次部署做完。八段抽取考试不在这一截的勾选里。
