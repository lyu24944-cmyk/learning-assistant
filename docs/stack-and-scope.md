# 框架和模块范围

这是一个学习助手。内容上有五块：每周复盘、课程问答、竞赛、实习、考研信息。11 月中旬先把竞赛截止日做成别人也能用的版本。选型的取舍写在这里，排期也写在这里。

## 现在用的框架

后端 FastAPI，前端 React + Vite，数据库是 SQLite。账号是自己做的邮箱和密码，密码只存 scrypt 哈希，登录态是 HttpOnly cookie 里的会话。不接 Clerk，也不接 Auth0。共享的已核对竞赛仍放在 `data/records.csv`，登录之后每个人都能读这份目录，接口不能改它。私人记录写进 SQLite，必须带 `user_id`。代码放在 Origin，运行放到 Railway，或者你已经在用的 Fly.io。

本地先看接口和页面：

```bash
pip install -r requirements.txt
python3 -m uvicorn src.api:app --host 127.0.0.1 --port 8010
```

另一个终端：

```bash
cd frontend
npm install
npm run dev
```

打开 http://127.0.0.1:5173 。先注册再登录。未登录时页面不显示时间线，直接请求 `/api/timeline`、`/api/records` 或 `/api/reminders` 会得到 401。登录后「今日提醒」只列出 7 天窗口内的已核对公历日期；2026-11-02 应显示「今日不发送」。截止日期仍是 CSV 里已核对的那几条，没有新编的日子。这一截不发邮件。数据库文件是 `data/app.sqlite`，不要提交进仓库。

## 这样选的好处

- 截止日期的判断已经在 Python 里。FastAPI 只负责把 `src/timeline.py` 的结果变成 HTTP，网页不再算一遍「剩余几天」。
- React + Vite 只做登录后的清单。开发时改页面刷新快，构建结果是静态文件，和 API 分开部署。
- SQLite 是一个文件。11 月中旬只有一个应用进程时，不用先搭数据库服务器。
- 11 张表有 SQLAlchemy 模型和 Alembic 版本表。加字段写一个 revision，空库和老库都能升到同一结构；建表和迁移只在启动时跑一次，不再每个连接执行 DDL。
- 邮箱和密码不依赖发信服务，注册不会卡在邮件商上。
- 批次 2 起，写请求要带 CSRF token，会话有服务端过期，失败次数记在数据库里。重置密码走运维命令，不接 SMTP。出现第一个「非运维用户」（不在本机、需要自助找回密码）时，SMTP 从「以后」变成「现在」，才允许加 `/forgot-password`；在那之前，CLI 是诚实的通道。细节见 [auth.md](auth.md)。

## 这样选的代价

- 本地要同时开 API 和前端两个进程。只跑其中一个，页面会提示读不到时间线。
- SQLite 仍然只允许一个写进程。`busy_timeout` 让并发写排队，但开第二个写进程仍可能锁库。2026-11-09 实测 WAL 在 Windows 上不稳定（4 写 4 读 × 3 轮，每轮都有 `attempt to write a readonly database`），所以默认保持 DELETE，不靠 WAL 解决多进程。
- 旧模块仍用 `sqlite3` 原生 SQL，新模块用 `session()`。换 Postgres 时，旧模块要先被改到、换成 SQLAlchemy 查询；`tests/test_dialect.py` 保证不会静默长出方言 SQL。
- Vite 不做服务端渲染。第一次打开要等接口返回，不适合靠搜索引擎获客。这个产品不靠那个。
- 手贴页面还没做。写入口 `POST /api/records` 已经要求登录，并且只写入当前用户的行。共享目录仍然只能改 CSV，不能从网页改。

## 为什么不选别的

**Next.js 单体。** 能把页面和接口放在一个 Node 进程里，少一个端口。代价是日期规则要么重写进 JavaScript，要么 Node 再去调 Python。两种都会把「未找到 / 已核对 / 7 天」拆成两处。这个助手的正确性靠那一套 Python，所以不把 Next.js 当本月的框架。以后若要服务端渲染，也只让它做页面，接口仍留在 FastAPI。

**Django。** 能做账号、后台和 ORM，但是这一截用不到模板和管理站点。现有代码是纯函数，不是 Django 的模型。为了包一层 HTTP 去背上整套框架，比 FastAPI 重，也没有少写日期规则。

**只用飞书。** 飞书多维表格适合自己核对几行，不适合作为别人打开的产品。每个用户都要有飞书账号，记录隔离、每周复盘、课程问答都不会长在那张表上。飞书保留为可选导出：`python3 -m src.export_feishu`。它不是注册、保存或提醒的前提。

## 什么时候换成 Postgres

同时满足下面任一条再换，不要为了「更正式」提前换：

- API 要开到两个及以上进程，并且都会写记录。
- 部署平台不能给 SQLite 一块稳定磁盘，文件会在重启后消失。
- 需要备份、恢复，而复制单个文件已经不够。

表仍然按 `user_id` 分开。连接串只在 `src/db/paths.py` 读一次：`DATABASE_URL` 优先，默认 `sqlite:///data/app.sqlite`。迁移用 `python -m alembic upgrade head`，老库第一次启动会自动备份并接管。换库时先确认 `tests/test_dialect.py` 仍通过，再把被用到的模块从 `sqlite3` 换成 `session()`；时间线规则和已核对日期不变。

## 各块什么时候做完

| 模块 | 何时算这一块做完 | 现在 |
| --- | --- | --- |
| 竞赛截止日、提醒、多用户 | 11 月中旬的 MVP。别人能注册，登录后看竞赛时间线；已核对的公历日期才进今天起 7 天；没有行就不发。 | 邮箱密码和 SQLite 会话已接上。登录后看到共享目录里的 4 条。手贴页面和部署还没做。 |
| 每周复盘 | MVP 上线之后的一周。每人记自己的一周，不和竞赛截止日期混在一张表里。 | 不做。 |
| 课程问答 | 12 月上旬。不挡住 11 月中旬。 | 不做。 |
| 实习、考研信息 | 竞赛稳定之后的阶段二再放开录入。`allowed_info_types` 里已经有「实习」和「考研」，本月 `info_type` 仍是「竞赛」。 | 不改配置去录入这两类。 |
| Coze / Dify 八段考试 | 和课程问答同属后面的阶段，不挡住上线。 | 本地评分函数可以跑，不算上线条件。 |
| 个人微信机器人 | 本月不做。 | 不做。 |

手贴时的日期规则不变：原文有公历年月日才写成 `YYYY-MM-DD`；相对日期或没有日期就写「未找到」，并且不参与提醒。本周不把抓网页当成默认录入。
