# 飞书提醒：照着点

提醒由飞书多维表格的工作流发送，不经过模型，不走个人微信，也不用本机 cron。接收人只选你自己。

本地可以先预览同一套筛选会发出什么。预览命令不会发飞书消息。默认记录文件已经是 `data/records.csv`；要对照下面的示例标题，必须写上示例表：

```bash
python3 -m src.reminder --records templates/records.example.csv --today 2026-11-08
```

以示例表、今天当作 2026-11-08 时，正文里应出现青柠数据分析赛、北区算法邀请赛、小城创新挑战赛、化学实验赛、湖边演讲赛。不应出现草稿隔离赛、本周五口头赛、已放弃的编程赛、纸上建模赛、周末程序赛。

把日期改成没有命中的一天，输出只有一行「今日不发送」：

```bash
python3 -m src.reminder --records templates/records.example.csv --today 2026-12-31
```

飞书侧没有命中时不要发这四个字，工作流的「不满足」分支保持空白。

官方说明（界面以你账号里看到的文字为准）：

- [工作流和自动化的触发条件与执行操作](https://www.feishu.cn/hc/zh-CN/articles/740947703250)
- [使用多维表格自动化流程](https://base.feishu.cn/helpcenter/ai8y3d44/tys0fnxv)
- 条件判断在工作流里，不在旧的「自动化」线性列表里。本流程用工作流。

## 1. 建公式字段「应提醒」

1. 打开「截止」数据表，点表头最右侧的 `+`。
2. 字段标题填 `应提醒`，类型选「公式」。
3. 点「编辑公式」。字段名从左侧「字段引用」点进去，不要只靠手打中括号。
4. 粘贴下面的公式，再把每个 `[字段名]` 换成点击插入的字段。`竞赛` 要和 `config/settings.json` 的 `info_type` 相同。

```
IF(
  ([核对状态] = "已核对") && ([是否参与提醒] = "是") && ([截止日期标注] = "已识别") && ([类型] = "竞赛") && NOT(ISBLANK([截止日期])) && ([截止日期] >= TODAY()) && ([截止日期] <= TODAY() + 7),
  "是",
  "否"
)
```

5. 点确认、确定。看两行：
   - 把「青柠数据分析赛」的截止日期改成明天，「应提醒」应为「是」（核对状态已经是已核对）。改完记下来，测完改回原日期。
   - 「草稿隔离赛」和「本周五口头赛」应为「否」。
6. 若保存提示函数不存在：先删掉 `NOT(ISBLANK([截止日期])) &&` 这一段再试。日期加减若报错，改用文末「不用公式的筛法」，查找记录不要依赖「应提醒」。

`TODAY()` 用的是飞书文档所在时区。把飞书个人设置里的时区调成北京时间，和 `Asia/Shanghai` 一致。

## 2. 建工作流

1. 打开这份多维表格，点左下角「工作流」。
2. 选「从空白开始」。名称填 `每日截止提醒`。
3. 触发器选「定时触发」。
   - 先不要设成每天。验收时设成「大约 10 分钟后的一次」，时区选北京时间（GMT+8）。
   - 通过验收后，再改成每天 `08:00` 重复。官方说明：自定义重复若填了结束日期，结束日当天不会触发。
4. 添加操作「查找记录」。
   - 数据表选「截止」。
   - 筛选选「满足所有条件」：`应提醒` 等于 `是`。
   - 查找内容勾选 `标题`、`截止日期`、`来源链接`。不要勾选整行无关字段。
5. 添加「条件判断」（If/Else）。
   - 判断对象选上一步「查找到的所有记录」。
   - 条件选「不为空」。若列表里没有「不为空」，改选「记录数大于 0」或界面上等价的「有记录」。
6. 「满足」分支里添加「发送飞书消息」。
   - 发送身份可用「多维表格助手」或你自己。
   - 接收人只选你自己，不要选班级群。
   - 卡片标题：`未来7天截止`
   - 正文用引用插入「查找到的所有记录」，只保留标题、截止日期、来源链接。若界面要逐字段写，排成三行：`标题`、`截止日期：` + 日期字段、`来源：` + 链接字段。多行记录要落在同一张卡片里，不要拆成每人一条以外的群发。
7. 「不满足」分支不要添加任何操作。不要在这里发「今日无事项」。
8. 点「保存并启用」。权限提示若出现，按页面要求用表格所有者身份启用。官方限制：能启用流程的人需要有这份多维表格的可管理权限，且与所有者在同一企业；个人版若按钮不可用，把验收改成「点击按钮时」触发的同一套查找和判断，接收人仍是你自己，并在清单里记下这个差异。

## 3. 做一次真实送达

1. 选一条你已经核对过、愿意用来试发的记录，把截止日期改成明天，应提醒变为「是」。备注或日期原句末尾加上「（测试日期，测完改回）」。
2. 另确认一条草稿或「未找到」的应提醒是「否」。
3. 等到单次定时触发，或使用画布上的运行 / 测试按钮（名称以界面为准）。
4. 通过标准：飞书里收到一张卡片，含那条的标题、截止日期、来源链接；草稿和未找到的标题不在卡片里。
5. 把测试记录的日期改回原文中的日期，删掉测试备注。
6. 再把所有测试行的应提醒调成「否」（或把截止日期改回窗口外），运行一次。这次你不应收到新卡片。
7. 两次都符合预期后，把触发器改成每天 08:00 重复并保存。没有命中的早晨保持安静。

## 不用公式的筛法

公式无法保存时，第 4 步的查找记录改为同时满足：

- 类型 等于 `竞赛`（或你的 `info_type`）
- 核对状态 等于 `已核对`
- 是否参与提醒 等于 `是`
- 截止日期标注 等于 `已识别`
- 截止日期 不为空
- 截止日期 属于「未来 7 天」

打开一条截止日期是今天的记录，看它是否进得了这个筛选。若「未来 7 天」不含今天，把日期条件改成条件组：满足「未来 7 天」或「是今天」中的任一，并且仍然同时满足前面五条。条件判断和「没有记录就不发」保持不变。

## 和模型的边界

Coze / Dify 的输出贴进表格时，核对状态保持「草稿」，是否参与提醒保持「否」。工作流里不要加「AI 生成文本」「修改记录」。抽取结果不会自己变成提醒。
